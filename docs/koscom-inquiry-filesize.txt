제목: [CHECK API 문의] tick_date 파일 크기 제한이 500MB에서 200MB로 변경되었는지 확인 요청 및 미수신 자료 제공 요청


안녕하십니까.

CHECK API tick_date로 체결 데이터를 수집하던 중, 파일 크기 제한 오류가 발생하고
있습니다. 제한값이 최근에 낮아진 것으로 보여 확인을 요청드리며, 그로 인해 받지 못한
자료의 별도 제공도 함께 요청드립니다.


1. 관측된 오류 메시지

   가. 2026년 8월 7일

       {"success": false,
        "message": "ERROR READ FILE. : File too large size(>= 500MB)."}

   나. 2026년 8월 12일

       {"success": false,
        "message": "ERROR READ FILE. : File too large size(>= 200MB)."}

   같은 endpoint, 같은 호출 방식인데 메시지의 임계값이 500MB에서 200MB로 바뀌었습니다.


2. 제한값이 낮아졌다고 판단한 근거

   동일한 (종목, 거래일) 조합을 8월 10일에는 정상 수신했으나, 8월 12일에는 거부되었습니다.

   예 — 005930 / 2026-06-05

       2026-08-10 00:10  요청 필드 10개  ->  정상 수신 (770,981건)
       2026-08-12 04:47  요청 필드  2개  ->  "File too large size(>= 200MB)" 로 거부

   요청 필드를 오히려 10개에서 2개로 줄였는데 거부되었습니다. 당사 요청이 커진 것이
   아니므로, 서버 측 임계값이 변경된 것으로 판단하고 있습니다.

   아래 3번 목록의 13건 중 12건이 이미 당사가 정상 수신해 보관 중인 조합입니다.
   즉 같은 파일을 며칠 전에는 받을 수 있었습니다.

   거래일        종목코드  종목명          시장     오류 임계값   기수신 여부

   '보유'는 이전에 정상 수신하여 당사가 데이터를 가지고 있다는 뜻입니다.
   이번에 추가 필드(F30614)를 보강하려다 거부된 건들입니다.

   '미보유'인 2026-06-02 / 005930 한 건은 체결 데이터 자체를 확보하지 못했습니다.
   해당 일자는 보관 기간(약 101일) 내이나 조회가 되지 않습니다.


4. data_list 로 필드를 줄여도 회피되지 않습니다

   2번 예시와 같이 필드를 10개에서 2개로 줄여도 동일하게 거부됩니다.
   제한이 응답 크기가 아니라 서버 측 원본 파일 크기를 기준으로 적용되는 것으로
   이해하고 있습니다. 맞는지 확인 부탁드립니다.


5. 문의 및 요청 사항

   가. 파일 크기 제한이 500MB에서 200MB로 변경된 것이 맞습니까?
       변경이라면 항구적인지, 일시적인 조치인지 알려주시면 감사하겠습니다.

   나. 현재 적용 중인 정확한 임계값을 알려주시면, 사전에 대상을 판별해 불필요한
       호출을 줄일 수 있습니다.

   다. 위 3번 목록 13건의 자료를 별도 파일로 제공받을 수 있는지 문의드립니다.
       특히 2026-06-02 / 005930 은 데이터 자체를 확보하지 못한 건입니다.
       (앞서 005930 / 2026-05-07 건은 별도 파일로 제공받은 바 있습니다. 감사합니다.)

   라. 제한을 회피할 수 있는 조회 방법이 있다면 안내 부탁드립니다.
       tick_date 에는 조회 범위를 나누는 파라미터(시간대, 건수, 페이지 등)가
       없는 것으로 확인됩니다.


6. 참고 사항

   - 등록 IP 환경에서 POST 방식(form-urlencoded)으로 호출하고 있습니다.
   - 제한에 걸리는 비율은 낮습니다. 2026년 8월 12일 기준 3,202건 호출 중 12건
     (약 0.4%)이며, 거래일에 따라 0~4건입니다.
   - 거부된 요청은 즉시 기록하고 재시도하지 않도록 조치했습니다.
