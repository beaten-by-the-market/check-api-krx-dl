# [문의] tick_date 특정 종목·일자 조합에서 `Error while performing Query.` 반복 발생

- **작성일**: 2026-07-27
- **대상 API**: `POST /stock/m222/tick_date` (NXT-KOSPI 체결정보)
- **증상**: **005930(삼성전자) / edate=20260507** 조합만 항상 실패. 동일 요청을 다른 날짜·
  다른 종목으로 바꾸면 정상. 재시도(4회, 시행일 3일에 걸쳐 총 8회 이상)에도 동일하게 실패.

## 1. 재현 요청

```
POST https://checkapi.koscom.co.kr/stock/m222/tick_date
Content-Type: application/x-www-form-urlencoded

cust_id=<발급받은 고객번호>
auth_key=<발급받은 인증키>
jcode=005930
edate=20260507
data_list=F16604,F15019,F15001,F15020,F15022
```

## 2. 응답

HTTP 200 이며 본문은 다음과 같습니다.

```json
{"success": false, "message": "Error while performing Query."}
```

`data_list` 를 빼고 전체 필드로 요청해도 동일합니다.

## 3. 이 조합만 실패한다는 근거 (실측)

### (a) 같은 날짜(2026-05-07)의 다른 종목은 전부 정상

그날 NXT 거래종목 **628개를 모두 조회해 628개 전부 성공**했습니다(총 6,838,954건 수신).
삼성전자만 목록에서 빠졌습니다. 같은 날 대용량 종목도 문제없이 응답했습니다.

| 종목코드 | 수신 건수 |
| --- | --- |
| 000660 (SK하이닉스) | 406,038 |
| 028050 | 322,982 |
| 011790 | 243,184 |

→ **"그 날짜의 데이터가 통째로 없다"로는 설명되지 않습니다.**

### (b) 같은 종목(005930)의 인접 거래일은 전부 정상

| edate | 수신 건수 |
| --- | --- |
| 2026-05-04 | 350,673 |
| 2026-05-06 | 854,332 |
| **2026-05-07** | **실패 (`Error while performing Query.`)** |
| 2026-05-08 | 593,301 |
| 2026-05-11 | 669,469 |
| 2026-05-12 | 859,377 |
| 2026-05-13 | 781,847 |
| 2026-05-14 | 539,542 |
| 2026-05-15 | 830,619 |

→ **"응답이 너무 커서 실패한다"로도 설명되지 않습니다.** 같은 종목이 05-12에 859,377건,
05-06에 854,332건을 정상 반환했고, 이는 05-07 예상 규모보다 큽니다.

### (c) 조회 시점이 보관 기간 내였음

당사 실측상 `tick_date` 보관 기간은 조회일 기준 약 101일입니다.
최초 실패 시점(2026-07-23)에 2026-05-07은 **77일 전**으로 보관 기간 내였고,
같은 요청을 2026-07-27(81일 전)에 재시도했을 때도 동일하게 실패했습니다.
(보관 기간을 벗어난 날짜도 같은 메시지를 반환하는 것으로 보이나, 본 건은 기간 내입니다.)

## 4. 문의 사항

1. 2026-05-07 005930 체결 데이터가 서버 측에 정상 적재되어 있는지 확인 부탁드립니다.
2. 적재 누락이라면 재적재가 가능한지, 가능하다면 예상 시점을 알려주시기 바랍니다.
3. `Error while performing Query.` 메시지가 **보관기간 초과**와 **서버 측 조회 실패**를
   구분하지 않고 동일하게 반환되는 것으로 보입니다. 두 상황을 구분할 수 있는 에러 코드가
   있으면 클라이언트에서 "재시도 무의미" 와 "재시도 필요" 를 판별할 수 있어 도움이 됩니다.

## 5. 참고: 사용 환경

- 인증: 등록 IP에서 POST(form-urlencoded) 호출, 다른 요청은 모두 정상 처리됨
- 동일 세션에서 초당 1건 이하로 순차 호출, rate limit 관련 메시지는 수신되지 않음
- 본 건 외 2026-04-03 ~ 2026-05-14 구간 18,551건 조회는 모두 정상 응답(1억 7,891만 건 수신)
